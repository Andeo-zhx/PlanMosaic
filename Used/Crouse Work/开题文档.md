## 一、选题背景与意义

### 1.1 项目背景

PlanMosaic 是一个**三端（Electron 桌面端 + Android + Uni-app）日程规划 AI 助手系统**。用户可以通过自然语言对话的方式管理日程、拆解任务、进行深度战略规划。系统核心交互方式基于 **Native Function Calling（OpenAI 兼容格式）**，底层实现的是"推理→行动"（Reasoning → Acting）的 Agent 范式。

截至本选题启动时，PlanMosaic 已经具备以下成熟功能：

- **14+ 工具集合**：涵盖日程 CRUD（查看/添加/修改）、冲突检测、任务管理、大任务管理、课表管理、智能分析、模板管理、价值货币化评估、ROI 计算器、里程碑规划、SWOT 分析、决策矩阵、网络搜索评估、任务时间估算等
- **Proposal 确认机制**：危险操作（删除/修改）生成可视化提案，用户确认后才执行，保障数据安全
- **思路链可视化**：桌面端与 Android 端均支持 `【思考】...【/思考】` 标记的推理过程折叠展示
- **双模式对话**：日常助手模式（日程管理）+ 深度规划模式（战略咨询），各有独立的 System Prompt 与工具集
- **流式输出**：SSE 实时推送，打字机效果
- **多模型支持**：DeepSeek + Qwen 双供应商，reasoner 模型自动切换

### 1.2 选题目标

本选题的目标**不是在空项目中从零搭建一个 Agent**，而是**在 PlanMosaic 现有生产级架构的基础上，深入理解和展示 ReAct（Reasoning + Acting）范式，并通过功能增强证明对该范式的掌握**。具体包括：

1. **理解并实现 Function Calling → ReAct 格式转换**：通过"转录"机制，将原生 Function Calling 的隐式工具调用过程翻译为显式的 ReAct 文本（Thought → Action → Observation → Final Answer），展示对两种 Agent 范式的深刻理解
2. **扩展工具覆盖领域**：新增网络搜索、ML 时间估算、日程健康度检查等工具，展示 Agent 的通用性
3. **引入小模型训练**：基于 scikit-learn 的 RandomForest 回归模型，实现可训练的任务时间预估器，展示 Agent 的持续学习能力

### 1.3 研究意义

| 维度 | 说明 |
|------|------|
| **理论价值** | 对 ReAct 范式与 Native Function Calling 进行对比研究，揭示两者在交互格式、控制流、工程复杂度等方面的差异与本质统一 |
| **工程价值** | 保留生产级的 Native Function Calling 稳定交互，同时通过转录机制满足课程对 ReAct 展示的要求——既不影响用户体验，又完整呈现 ReAct 过程 |
| **教学价值** | 通过实际代码（如 AgentRepository.kt 的 `callWithTools` 递归循环）展示 Agent 的状态管理、工具调度、多轮对话等核心机制 |
| **扩展性** | 新增工具和 Python 微服务的旁路设计，不侵入现有架构，可直接用于后续迭代 |

## 二、技术调研

### 2.1 ReAct 范式 vs Native Function Calling

Agent 编程的核心是让大语言模型（LLM）在"推理"和"行动"之间循环，直到完成任务。目前主流有两种实现方式：

#### 2.1.1 ReAct 范式

ReAct（Reasoning + Acting）由 Yao et al.（2022）提出，其核心是**显式的 Thought → Action → Observation 循环**：

```
Question: 用户问题
Thought: 我需要先做什么...
Action: tool_name(param1="value1")
Observation: 工具返回结果
Thought: 基于结果，下一步应该...
Action: another_tool(...)
Observation: ...
Thought: 信息足够了
Final Answer: 最终回答
```

**特点**：
- **透明度高**：每一步的思考过程都显式暴露，便于调试和审计
- **手写解析**：需要自己实现文本解析器来提取 Thought、Action 等标记
- **控制流自定义**：需要手写循环逻辑来管理多步工具调用
- **工程复杂度高**：文本解析容易出错，格式约束需要精确的 Prompt Engineering

#### 2.1.2 Native Function Calling

Native Function Calling 是 OpenAI 推出的 API 原生能力，DeepSeek、Qwen 等主流模型均已兼容。其底层同样是"推理→行动"，但格式不同：

```json
{
  "role": "assistant",
  "content": null,
  "tool_calls": [{
    "id": "call_abc123",
    "function": {
      "name": "view_schedule",
      "arguments": "{\"date\":\"2026-05-20\"}"
    }
  }]
}
```

**特点**：
- **API 原生支持**：`tool_choice: "auto"` 自动判断是否需要工具调用
- **结构化返回**：JSON 格式的工具调用，不需要手写解析器
- **过程隐式**：推理过程被封装在 API 内部，用户看不到中间步骤
- **稳定可靠**：生产级方案，经过大规模验证

#### 2.1.3 本项目的实践策略

**保留 Native Function Calling 作为生产交互方式，通过"转录"机制将隐式的 tool calls 翻译为显式的 ReAct 文本。** 这样做的理由：

1. 转录过程本身就是对两种范式的深度理解——需要识别每个 tool call 的语义、推断对应的 Thought、匹配 Observation
2. 不影响现有用户交互体验
3. 生成的 ReAct 文本可以直接用于课程展示和答辩演示

#### 2.2.3 Android 端递归工具调用

在 [AgentRepository.kt](file:///d:/Trae%20CN/Projects/PlanMosaic/PlanMosaic%20AndroidStudio/app/src/main/java/com/example/planmosaic_android/data/repository/AgentRepository.kt) 中，`callWithTools` 方法实现了**递归的多轮工具调用循环**：

```kotlin
// AgentRepository.kt - callWithTools 方法（节选）
private suspend fun callWithTools(
    messages: MutableList<JsonObject>,
    appData: AppData,
    apiKey: String,
    provider: String,
    useReasoner: Boolean,
    depth: Int,
    tools: List<JsonObject> = AgentTools.AI_TOOLS_JSON
): ChatResponse {
    if (depth > 10) {
        return ChatResponse(content = "工具调用轮次过多，请简化您的请求。")
    }

    val result = aiApiClient.chat(apiKey, provider, messages, tools, useReasoner)

    if (result.toolCalls.isEmpty()) {
        return ChatResponse(content = result.content, shouldRefresh = false)
    }

    // 执行所有工具调用
    messages.add(aiApiClient.assistantMessage(result.content, result.toolCalls, null))
    for (tc in result.toolCalls) {
        val toolResult = AgentTools.executeTool(tc.function.name, tc.function.arguments, currentAppData)
        messages.add(aiApiClient.toolResultMessage(tc.id, toolResult.json))
    }

    // 递归调用，让 AI 处理工具结果
    val followUp = callWithTools(messages, currentAppData, apiKey, provider, useReasoner, depth + 1, tools)
    return followUp.copy(...)
}
```

该方法的递归设计展示了一个完整的 Agent 控制循环：调用 LLM → 获取 tool calls → 执行工具 → 将结果返回 LLM → 继续循环或结束。这正是 ReAct 范式在工程上的体现。

### 3.2 核心功能实现

#### 3.2.1 ReAct 对话转录

**后端实现**（已在 [server.js](file:///d:/Trae%20CN/Projects/PlanMosaic/server.js) 第 921-1011 行实现）：

- 端点：`POST /api/generate-react-log`
- 输入：对话 messages 数组（含 `tool_calls` 和 `tool` 角色消息）
- 处理逻辑：
  1. 遍历 messages，提取 `user` 消息作为 `Question`
  2. 识别 `assistant` 消息中的 `tool_calls`，为每个 tool call 生成对应的 `Thought`（基于工具名称的语义映射表）和 `Action`
  3. 向前搜索匹配的 `tool` 消息，提取结果作为 `Observation`（超过 300 字符自动截断）
  4. 识别最后的 `assistant` 纯文本消息作为 `Final Answer`
- 输出：标准 ReAct 格式文本

**转换示例**：

```
原始 Function Calling 流程：
  user: "帮我查一下番茄工作法"
  assistant: tool_calls=[{name:"web_search_evaluate", args:{query:"番茄工作法"}}]
  tool: "番茄工作法核心是25分钟专注+5分钟休息..."
  assistant: content="番茄工作法是一种时间管理方法..."

↓ 转录为 ReAct 格式 ↓

  Question: 帮我查一下番茄工作法

  Thought: 用户需要搜索相关信息，我将搜索"番茄工作法"来获取资料。
  Action: web_search_evaluate(query="番茄工作法", purpose="最佳实践", max_results=5)
  Observation: 番茄工作法核心是25分钟专注+5分钟休息...

  Thought: 我已经获得了所需的信息，可以给出最终答案了。
  Final Answer: 番茄工作法是一种时间管理方法...
```

#### 3.2.3 Python ML 微服务

Flask 服务运行在 **端口 5100**，提供 4 个 REST 端点：

| 端点 | 方法 | 功能 | 调用频率 |
|------|------|------|---------|
| `/api/estimate` | POST | 接收任务名称和类别，返回预估分钟数 | 高频（每次时间估算请求） |
| `/api/train` | POST | 用当前数据集重新训练模型 | 低频（用户手动触发） |
| `/api/collect` | POST | 收集用户实际耗时数据（任务名+预计+实际+类别） | 中频（每次完成任务后） |
| `/api/status` | GET | 返回模型状态（训练样本数、R² 分数、最后训练时间） | 低频（状态查询） |

**技术细节**：
- **向量化**：TfidfVectorizer(max_features=500, ngram_range=(1,2))，对中文任务名提取字符级和双字符级特征
- **模型**：RandomForestRegressor(n_estimators=100, max_depth=10, random_state=42)
- **首次启动**：自动检测模型文件是否存在，不存在则用 1000 条预置数据训练
- **数据持久化**：训练数据存储为 JSONL 文件，模型序列化为 `.pkl` 文件
- **降级**：server.js 优先调用 Python 服务，超时 3 秒后自动使用 LLM 降级估算

```
Observation: 明天下午14:00-15:30已有"团队会议"；16:00-16:45已有"代码评审"

Thought: 15:30-16:00有30分钟空闲，16:45后空闲。每个番茄钟25分钟+5分钟休息，安排两个1小时。
Action: add_schedule(date="明天日期", timeSlots=[...])
Observation: 日程添加成功

Thought: 我已经获得了所需的信息，可以给出最终答案了。
Final Answer: 已为你明天下午安排了两个番茄钟时段：16:45-17:10和17:15-17:40。专注时记得关闭手机通知哦～🍅
```
